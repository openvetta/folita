# 0005. 无 Dock 图标：只以菜单栏图标常驻

- 状态：已采纳
- 日期：2026-10-21

## 背景

Folita 是呼出式剪贴板工具：主线操作是在任意应用里按快捷键唤出剪贴面板，主窗口只是设置。此前应用以常规应用运行，同时有 Dock 图标与菜单栏图标（`MenuBarExtra`），两者都是入口，但 Dock 图标只提供「切回本应用」这一件事，反而在切换应用、⌘Tab 和程序坞里占用位置。

Dock 图标此前还承担另一项职责：通用设置里的 12 款应用图标只改变运行期间的 Dock 图标。去掉 Dock 后，这份选择需要新的落点。

## 决策

- 构建设置声明 `INFOPLIST_KEY_LSUIElement = YES`，应用以 accessory（无 Dock 图标）方式运行，只以菜单栏图标常驻。
- 菜单栏图标显示通用设置里所选的应用图标，彩色（非模板）渲染。图标按 18 pt 重新绘制后再交给菜单栏：直接把 512 pt 原图交出去会让状态栏项按原图尺寸撑开。图标资源缺失时退回剪贴板符号，保证菜单栏总有一个入口。
- 主窗口通过 `.defaultLaunchBehavior(.suppressed)` 不随启动弹出，并用 `.restorationBehavior(.disabled)` 关闭窗口状态恢复；入口是菜单栏的「Open Main Panel」（⌘,）。登录时启动因此也不会弹窗。
- 主面板打开期间把激活策略切回 `.regular`，关闭后回到 `.accessory`：设置窗口是唯一需要程序坞图标的界面，平时则完全不占程序坞与 ⌘Tab。策略切换由 `DockIconVisibility` 收敛，主面板视图的出现/消失调用它。
- 运行期仍设置 `NSApp.applicationIconImage`（沙盒内无法改写 bundle 图标），使应用自己的弹窗等系统界面跟随所选图标。
- 剪贴面板里的 ⌘, 也能打开主面板：面板与 AppDelegate 都是 AppKit 代码，拿不到 SwiftUI 的 `openWindow`，由菜单栏标签上常驻的 `WindowOpeningBridge` 把动作交给 `MainWindowRouter`，菜单栏项与面板快捷键因此共用同一条打开路径。

## 备选方案

- **保留 Dock，仅隐藏菜单栏图标**：剪贴面板与全局快捷键不依赖 Dock，但关闭主窗口后用户只能从 Dock 或 ⌘Tab 回来，且未选中主窗口时没有常驻入口。未采用。
- **完全自管 `NSStatusItem`**：可以精确控制状态栏项的图片与点击行为，但要自行处理菜单构建、快捷键提示、本地化与 Liquid Glass 菜单样式，替换掉现有 `MenuBarExtra` 的全部收益。未采用。
- **保留启动时弹出主窗口**：与「无 Dock 应用」的心智不符，登录时启动还会每次都弹设置窗口。未采用。
- **始终不显示程序坞图标**：更彻底，但主面板成为唯一的常规窗口后，用户在 ⌘Tab 里找不到它，也无法从程序坞把设置窗口叫回来。未采用。

## 后果

- 用户不能再从 Dock 或 ⌘Tab 切到 Folita，菜单栏图标与全局快捷键成为唯一入口；菜单栏图标因此必须是可识别的应用图标。
- `MenuBarExtra` 只保留高频或全局入口：显示面板、打开主面板（⌘,）、检查更新、退出。暂停记录是低频开关，收敛到隐私设置页，避免菜单被一次性操作挤长。
- 12 款应用图标不再影响 Dock 与访达，只影响菜单栏、剪贴面板顶标、关于页与应用弹窗。
- 激活策略在主面板打开时变为 `.regular`：这段时间应用也会出现在 ⌘Tab 与程序坞里，关闭窗口后立即回到 accessory。
- 若将来需要恢复常驻 Dock 图标，去掉 `LSUIElement`、两条 Scene 修饰符与 `DockIconVisibility` 的调用即可，其余逻辑不依赖运行方式。
